# 《AI主权》出版标注规范

> 本目录服务编辑、设计、审校与组装，不进入纸书正文。

## 一、书稿单元

- **章级单元**：每章目录中的 `00_章节导读.md`，保存章题、开场、章级出版状态。
- **小节单元**：每个二级标题单独一个 Markdown 文件；三级标题继续留在所属小节，避免把完整论证切得过碎。
- **辅文单元**：书前、附录与出版工作台暂不强制拆分，按实际出版功能管理。

## 二、文件头字段

每个章级或小节文件以 YAML 元数据开头。这些字段用于生产管理，组装时不进入正文。

| 字段 | 含义 | 使用规则 |
|---|---|---|
| `unit_type` | `chapter` 或 `section` | 区分章级开场与正文小节 |
| `part` | 所属部 | 与正式目录一致 |
| `chapter` | 章号 | 序章、第一章至第七章、结语 |
| `section` | 小节号 | 章内唯一，跟随文件顺序 |
| `title` | 正式标题 | 改标题时须同步文件名与目录 |
| `order` | 组装顺序 | `00` 为章导读，其后连续编号 |
| `editorial_stage` | 出版编辑阶段 | 按下方状态流转 |
| `fact_check` | 事实核验要求 | 涉及时效事实时写明复核日期或范围 |
| `artwork` | 配图状态或图号 | 无图也要明确标为“无预设” |

## 三、出版状态

统一使用以下状态，不使用“差不多”“基本完成”等模糊说法：

1. `待出版初审`：结构已定，尚未完成出版社口径初审。
2. `初审已修`：内容、导向、版权和事实问题已按初审意见处理。
3. `复审已修`：语言、术语、标题层级、图表和注释体例已统一。
4. `终审待定`：只剩作者、出版社或装帧层面的确认项。
5. `出版冻结`：正文、图表、尾注与版式引用均已锁定；新事实不再直接写入。

若一章只有部分小节通过审校，章级状态取该章中最早的未完成阶段，不能用平均进度代替缺口。

## 四、章级出版检查

章级检查关注完整阅读体验：

- 本章只承担一个核心任务，开场困境与结尾判断能够闭合；
- 小节顺序形成递进，不依赖“如前所述”维持结构；
- 人物、案例、技术解释和抽象论证的节奏不过度集中；
- 本章图稿编号连续，图题、正文提及和图稿清单一致；
- 所有脚注在精选尾注中存在唯一定义；
- 与前后章没有重复定义或结论抢跑。

## 五、小节出版检查

小节检查关注可独立编辑：

- 一个小节只承担一个主要判断；
- 标题能概括判断，不只是主题标签；
- 技术术语首次出现有日常语言解释；
- 连续抽象论述不超过三个自然段；
- 事实具有来源、截至日期和适当置信边界；
- 案例不把项目方口径写成普遍结论；
- 开头能够承接上一节，结尾能够把问题交给下一节；
- 配图必须减少理解成本，不能只是装饰。

## 六、图稿标注

正文中的图稿需求使用 HTML 注释，不进入排版正文：

```markdown
<!-- 图稿需求：图5-2；具体形式、位置、构图、版权与交付要求见 90_出版工作台/02_图稿清单.md。此注释不进入排版正文。 -->
```

图号、位置、读者任务、图形结构、数据来源、版权方式和交付状态统一维护在图稿清单中。没有明确读者任务的图不立项。

## 七、组装与校验

`tools/book_structure.py` 是正式结构工具：

- `validate` 检查章目录、文件顺序、标题层级与小节数量；
- `assemble <输出路径>` 按正式顺序组装连续正文，并自动去掉 YAML 元数据；
- 图稿 HTML 注释保留在编辑组装稿中，交付排版前再统一剥离。
