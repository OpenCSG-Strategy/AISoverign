# 飞书同步

书稿和飞书知识库里的[《主权 AI 书籍》](https://opencsg-china.feishu.cn/wiki/IWEIwQby4iGx19kiCiCcGMBpnAc)双向同步。仓库是底稿，飞书是大家一起读、一起改的地方。

## 怎么运转

- **仓库到飞书。** 每次有改动推送到 `main`，GitHub 上的“同步到飞书”任务会组装全书，整篇写入这篇文档，插图一起上传，链接不变。文档开头一行写着最后同步的时间、对应的提交和一个校验值。
- **飞书到仓库。** 同事可以直接在飞书里改。每次写入之前，任务会先读一遍文档，和校验值对不上，就说明有人改过。这时任务不会覆盖，而是在仓库里开一个“飞书上有待拉回的修改”的 issue，列出改了哪几段、原文和现在的文字、文档最后修改时间。把这些改动改进对应的 md 文件，推送以后再同步。
- **定时检查。** 每天北京时间 9 点和 17 点，任务只检查一遍飞书上有没有新修改，有就开 issue，不写入。
- **谁的改动算数。** 按修改时间判断。飞书上的修改比仓库里同一段的提交晚，就以飞书为准；仓库后来又改过同一段，两边对照着合并，拿不准的问作者。

## 第一次配置

1. **飞书自建应用。** 在飞书开放平台（open.feishu.cn/app）的应用里开通下面几项权限，发布版本：
   - 查看、编辑和管理新版文档（`docx:document`）
   - 文本内容转换为云文档块（`docx:document.block:convert`）
   - 上传图片和附件到云文档中（`docs:document.media:upload`）
   - 查看知识库（`wiki:wiki:readonly`）
2. **给应用文档权限。** 打开这篇飞书文档，点右上角“…”，选“更多 → 添加文档应用”，把应用加进来，给“可编辑”权限。
3. **把密钥存进 GitHub。** 仓库的 Settings → Secrets and variables → Actions，新建两个 Repository secret：`FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`。目标文档已经写在脚本里；要换一篇文档时，再加一个 `FEISHU_DOC`，值为文档链接。
4. **跑第一次。** 在 Actions 页面打开“同步到飞书”，点 Run workflow。

使用国际版 Lark 时，再加一个 secret：`FEISHU_BASE`，值为 `https://open.larksuite.com`。

## 文档里会有哪些变化

- 飞书不支持脚注，正文里的脚注标记改成“［1］”这样的序号，注释原文留在附录B原来的位置，也换成同样的序号。拉回修改时要把序号换回 `[^key]`。
- 每张图下面加一行图题。

## 在本地检查

- `python3 tools/feishu_sync.py --dry-run 输出.md` 只生成准备上传的 Markdown，不连接飞书。
- `python3 tools/feishu_sync.py --check` 只检查飞书上有没有新修改，需要密钥。
- 确认飞书上的修改可以丢掉时，设 `FEISHU_FORCE=1` 再运行，会直接覆盖。
