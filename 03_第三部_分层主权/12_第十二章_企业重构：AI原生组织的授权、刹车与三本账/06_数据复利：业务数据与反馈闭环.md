## 数据复利：业务数据与反馈闭环

在所有智能资产里，数据最特别。模型、框架和工具会过时，爱彼迎的十三个模型哪个快、哪个便宜就多用哪个；高质量的业务数据和反馈却会越攒越多，越用越值钱，像复利一样。

企业最该积累的，是那些只有自己能产生的东西：客户真实提出的问题，专家改过的稿子，销售赢单和丢单的原因，设备的故障记录，客服收到的投诉。很多这类数据是在活干完以后才出现的。工程师改掉了模型写错的设备编号，顾问删掉了一句不该写进客户邮件的推测，一次投诉暴露出某类客户总在同一个环节被分错。这些修改记录了模型和现实差在哪里。

如果它们只回流给供应商，企业等于在帮别人改进模型，哪天换了模型，同样的错还得重新犯一遍。如果全部永久保存、默认拿去训练，又会把最敏感的客户经历和商业秘密堆在一处。比较稳妥的办法是分拣：一部分变成测试题，一部分写成明确的业务规则，一部分用来更新知识库，只有审查过的少量材料才拿去训练。更常见的情况是，这些经验只留在某个软件服务的隐藏记忆里、某位员工的聊天记录里，或者一个导不出来的向量数据库（把文字转成一串数字、供模型检索用的数据库）里。企业用 AI 越多，积累就越多地落在平台一侧。

### 数据也会往外流

数据还可能在没人注意的时候留在别处。二〇二五年五月十三日，在《纽约时报》起诉 OpenAI 和微软侵犯版权的案子里，美国纽约南区联邦法院的治安法官奥娜·王（Ona T. Wang）命令 OpenAI 保存并单独存放 ChatGPT 的全部输出日志，用户已经删除的对话也在其中。在这之前，删掉的对话一般在三十天内清除。命令落在普通用户和 API 用户身上，企业版、教育版和签了零数据保留协议的 API 客户不受影响。这项保存义务到二〇二五年九月二十六日才结束。[^p15-openai-preservation]

一家公司的员工如果用个人账号把合同和代码贴进对话框，这四个多月里，这些内容就和一场与公司无关的官司绑在了一起，删也删不掉。签了企业合同的公司，则在这道命令之外。

所以要给数据划路。在应用和模型之间设一个统一入口，业内叫模型网关。谁在调用，哪些数据可以送到外部模型，哪些只能在本地处理，哪些根本不该交给模型，该用哪个模型，出了问题切到哪条备用线路，都在这里决定。备用模型要平时就跑同一套真实测试，合同里写着“支持多模型”，到了出事那天也可能切换不过去。供应商的合同里还要写清楚，企业的数据和反馈能不能被拿去训练对方的模型，合同结束以后多久删除。

第七章讲过高质量数据为什么值得长期积累。放到一家企业里，有一个简单的检验办法：换掉当前的模型供应商以后，下一个模型能不能用上过去三年积累的测试题、改稿记录和失败案例。
