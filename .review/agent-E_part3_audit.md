- **核心数据点**：① 四道门分别是开放接口（API）、开放权重、开放模型、开源AI；② 权利维度为查看/运行、研究、修改、再分发与参与治理，材料维度为架构、参数、训练数据说明、训练/评测代码、检查点、评测和文档；③ OSI的Open Source AI Definition 1.0强调使用、研究、修改、分享，Linux Foundation的Model Openness Framework强调逐组件核验；④ FMTI 2025用100项指标检查透明度，开放权重与透明度相关但不能互相替代；⑤ Apache 2.0、MIT与社区/定制许可证只放在“法律权利”一层，不能替代训练数据、检查点和维护透明度。来源锚点：`[^p10-open-definitions]`、`[^p10-olmo]`、`[^p10-fmti]`。
- **构图建议**：上半部做四列“门”：每列固定两行“获得什么 / 仍缺什么”，用累积材料条而非简单从低到高打分；下半部做三条长期落点带：API更常对应集中运营的前沿/高责任服务，开放权重形成通用基础层，严格开源形成科研与公共品层，开放模型作为研究、审计和产业适配的桥梁跨接后两层。底部单列边界：“开放材料 ≠ 已完成审计；法律复制权 ≠ 现实复制能力”。不要把四类画成必然升级路线。

### 图11-2　数据空间与联邦学习：共享什么，移动什么

- **节标题 / 主题 / 缺图原因**：第十一章1“分布式协作的两条技术路径”。两种路径都避免先把全部控制权交给一个中心，但交换对象不同；只用文字容易把“数据空间”误解成数据永不移动，也容易把“联邦学习”误解成天然隐私安全。
- **核心数据点**：① 数据空间把发现、授权、传输、处理和追责拆开；数据携带来源、质量、用途、再转交、期限和结果回馈条件；数据不一定永远留在原处；② 联邦学习把初始模型送到本地训练，再将更新交给协调方汇总，原始病历等记录留在本地；③ 模型更新仍可能泄露特征或被恶意更新投毒；④ 防护包括安全聚合、差分隐私、加密、参与者验证和异常检测，且隐私、效用与恶意更新识别之间存在取舍；⑤ 共同问题是研究目标、弱势群体表现、价值分配、退出和责任，不能只靠技术优化。来源锚点：`[^p9-data-act]`、`[^p11-fl]`；联邦学习技术结论为多源技术资料一致，不代表具体临床效果。
- **构图建议**：左右双栏共用三家机构的解释性场景。左栏“数据空间”画目录/身份/语义/合同控制面，按条件让数据或结果流动；右栏“联邦学习”画初始模型→本地训练→受保护更新→聚合→再下发循环。两栏底部分别列风险：强势参与者/合规成本，与更新泄露/投毒/群体偏差；中间只写共同点“边界可表达、授权可撤回、行动可追责”，不要写成“两者都不移动原始数据”。图注注明三家医院是解释性场景，不是临床成效声明。
- **落位**：第1节末尾，综合两个三级小节。

### 图11-3　同一智能体穿过四层主权

- **节标题 / 主题 / 缺图原因**：第十一章2“协同主权的层级关系”。正文的层级是个人、组织单元、企业、国家与城市四层，不是彼此孤立的控制台；现有序章图只说明一般四级主权，本节还需要显示同一任务跨层时授权、数据、责任与申诉怎样传递。
- **核心数据点**：① 个人：表达意图、限定授权、保留迁移/异议；② 组织单元（部门）：数据契约、属地执行、隔离与协同；③ 企业：工程生命周期、共同底座、外部供应商替换与恢复；④ 国家与城市：法律、公共监督、跨境合作，同时不得取消公民申诉与退出；⑤ 同一智能体可能从个人设备接受指令，经部门平台调用企业服务，并受国家/城市法律约束；⑥ 外层另标跨境共同规则与语言/知识多样性，不能把“全球标准”变成少数人的默认值。来源锚点：`[^p11-un-dialogue]`、`[^p11-unesco-language]`。
- **构图建议**：不用再画与图序-6相同的同心圆，改用一条横向任务链穿过四个责任域。每个域固定两行“本层可授权 / 本层不能外包的责任”，域与域之间标身份、数据契约、执行凭证、申诉/反馈四类双向接口；最上方画“同一智能体”，最下方画责任断裂最容易发生的三个接口。国家与城市合并为第四层，避免标题写“四层”而图中出现五层。
- **落位**：第2节“同一个智能体可能同时跨越四层”段之后。

### 图11-4　AI原生组织的任务—证据—接管—学习闭环（合并型候选）

- **节标题 / 主题 / 缺图原因**：优先落第十一章5“工作从职位流向任务”，并覆盖第9—13节。组织半章先后讲任务拆分、人的角色、组织记忆、智能体岗位边界、管理接口和十项检验，但目前没有一张总图说明这些部件怎样组成运行闭环；逐节各画一张会放大图量并产生重复。
- **核心数据点**：① 任务单位包含目标、状态、权限、证据和结果，并有明确委托人、有限权限、责任人和停止条件；② 工作在大模型、确定性软件、智能体与真人之间分配；③ 人的四类职责是定义问题、设计边界、验证与反驳、承担与接管；④ 组织记忆分事实/规则与运行经验两层，均需来源、版本、有效期和结果反馈；⑤ 智能体六项岗位边界是唯一身份、委托人、工具/数据、预算与有效期、需人工批准的动作、任务结束后的凭证清理；⑥ 经验数据可作为旁注而非因果证明：66家企业/7,137名知识工作者实验中，实际使用者每周少约2小时邮件时间但任务数量/构成无明显变化；AI原生企业结构数据来自年轻风险投资公司工作论文，跨场景外推有限。来源锚点：`[^p11-individual-ai]`、`[^p11-long-horizon-work]`、`[^p11-agent-identity]`、`[^p11-ai-native-firms]`。
- **构图建议**：中央五段闭环“任务定义→分配与执行→证据/结果→例外与人工接管→带来源的组织记忆→下一版任务”；上方用身份、权限、预算、期限、停止条件做贯穿护栏；下方区分概率判断、确定性规则、人类裁量三类接口。把第13节前七问映射到运行闭环、后三问放在外圈作为责任/人才/收益分配约束。不要做0—3评分、总分或无依据的健康阈值。
- **落位**：第5节“目标被拆成任务，状态、权限、证据和结果都能被描述”段之后；后续各节可在排版层引用同一图，不必新增图11-5—图11-13。
