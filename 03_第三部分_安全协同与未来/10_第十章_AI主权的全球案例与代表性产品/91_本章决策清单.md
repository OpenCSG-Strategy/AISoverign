# 第十章决策清单

> 本清单面向"想用 AI 主权案例指导决策"的三类读者:**企业决策者**(判断技术 / 供应商选择)、**政策制定者**(评估监管路径)、**投资人**(识别产业机会)。每条决策均与第十章具体案例对应,可在 5–7 月窗口内的数据基础上做出选择。

## 一、企业决策者(技术 / 供应商选择)

### 决策 1:是否把核心生产系统的安全分析能力从"闭源 API 调用"切换为"开源模型本地部署"?

**对应案例**:10.1 案例 3(OpenAI Agent 失控 + 智谱救场)
**决策依据**:Hugging Face 1.7 万条攻击日志被多家闭源模型 API 拒接(护栏无法区分"取证方"与"攻击者"),最终采用智谱 GLM-5.2 在自有基础设施完成取证,数据未出域。
**行动建议**:
- [ ] 评估自有生产系统的安全分析能力是否依赖第三方闭源 API
- [ ] 若依赖,需评估"被拒接"风险场景下的业务连续性
- [ ] 优先采用开放权重模型(GLM-5.2 / Mistral Large 3 / Qwen3.6 等)在自有基础设施部署关键安全能力
- **风险提示**:开放权重模型的"模型版本管理"与"安全更新机制"需自行建设,需配套 MLOps 能力

### 决策 2:企业级 AI 私有化部署是否优先采用"国产 + 兼容 HF SDK"的工具链?

**对应案例**:10.6(OpenCSG CSGHub 兼容 HF SDK + csglite 30 分钟 13B-70B 部署)
**决策依据**:CSGHub 的 Python SDK 与 Hugging Face 兼容,降低从全球开源生态向中国本土迁移的工程门槛;csglite 把企业内网部署时间从数日压缩到 30 分钟。
**行动建议**:
- [ ] 评估企业现有 AI 工具链是否依赖 HF 生态
- [ ] 若依赖,优先选择"SDK 兼容"的国产替代(CSGHub)以降低合规风险
- [ ] 部署时间窗口是否可压缩(< 1 天 vs 数日)作为选型关键指标
- **风险提示**:开源生态的"长期可维护性"需评估社区活跃度与企业服务能力

### 决策 3:是否采用"主权 AI 旗舰模型"(Mistral / 智谱 / DeepSeek / Sarvam)替代部分 OpenAI / Anthropic 用例?

**对应案例**:10.7(Mistral 法德市场份额超 OpenAI + 智谱港股 IPO + Sarvam C 轮)
**决策依据**:Mistral 在法、德两国企业级 LLM 采购份额 2026 Q2 首次超过 OpenAI;智谱港股 IPO 后 ARR 百亿美元(待验证);Sarvam 印度主权模型合作伙伴;DeepSeek V4-Flash 1 元/百万 token 全球最低。
**行动建议**:
- [ ] 评估"主权 AI 旗舰模型"在 3 个层面的可用性:**市场份额**(Mistral 类)、**全栈国产化**(智谱类)、**性价比**(DeepSeek 类)、**本土语言**(Sarvam 类)
- [ ] 在"非关键业务"场景优先试点主权模型,降低切换风险
- [ ] 评估"主权模型"的资本背书与上市预期对长期可维护性的影响
- **风险提示**:主权模型的"模型更新节奏"与"安全补丁机制"可能与闭源厂商不同,需建立内部评估流程

## 二、政策制定者(监管路径)

### 决策 4:监管路径选择——"规则驱动"(欧盟)、"投资审查"(美国)、"基础设施型"(中东 / 印度 / 韩国)?

**对应案例**:10.3(欧洲 Omnibus 延期)、10.4(中东 / 印度)、10.5(韩国 MSIT)
**决策依据**:欧洲 Annex III 延期 16 个月,Annex I 延期 24 个月;沙特 770 亿美元 + 11 个 DC,阿联酋 5 GW 园区;印度 38,000 GPU + 1 GW 园区 + Sarvam;韩国 550 万亿韩元 + 35,200 B200。
**行动建议**:
- [ ] 评估本国 / 本地区的资源禀赋:监管能力(欧洲)、资本能力(中东)、性价比(印度)、全栈能力(韩国)
- [ ] 监管路径选择需与产业能力匹配——"规则走在能力前面"会引发 Omnibus 式延期
- [ ] 跨主权 AI 联盟(SoftBank × 法国 5 GW)是 2026 年中的新型产业组织,值得在监管设计中预留接口
- **风险提示**:任何一种单一路径都难以独立支撑"主权 AI 可实现性",建议采用"主导 + 辅助"的组合策略

### 决策 5:开放权重模型是否纳入本国 AI 监管框架?

**对应案例**:10.1 案例 1(7-24 联名信 35 家)+ 10.1 案例 4(Anthropic 缺席 + 7-27 长文)
**决策依据**:7-24 联名信主张"开放权重 = 主权 AI",Anthropic 反驳"开放权重模型本身更便于搭建 AI 安全防护机制"——两种立场均有产业证据支撑。
**行动建议**:
- [ ] 评估开放权重模型在 4 个维度的政策含义:**创新促进**(HF 179 万+ 模型)、**安全风险**(模型被滥用扩散)、**合规追溯**(Hugging Face 智谱救场事件)、**地缘政治**(Anthropic 指控 DeepSeek 蒸馏)
- [ ] 借鉴 NIST AI RMF 1.2 的"开放权重模型治理"独立章节作为参考
- [ ] 避免对开放模型施加过早限制,但需建立"工业级蒸馏"等具体边界
- **风险提示**:过早限制可能错失产业机会;过晚限制可能形成既成事实

## 三、投资人(产业机会识别)

### 决策 6:主权 AI 旗舰模型 / 基础设施 / 工具链三个赛道,优先选择哪一个?

**对应案例**:10.6 + 10.7
**决策依据**:
- **旗舰模型赛道**:Mistral(法德市场份额超 OpenAI)+ 智谱(港股 IPO + A+H 上市预期)+ Sarvam(SoftBank 领投 C 轮)+ DeepSeek(70 亿美元融资 + V4 峰谷定价)
- **基础设施赛道**:沙特 770 亿美元 / 阿联酋 5 GW / 印度 1 GW + 38,000 GPU / 韩国 5 万+ GPU / 日本 27,500 Rubin / Campus AI 1.4 GW
- **工具链赛道**:Hugging Face(45 亿美元估值)+ OpenCSG(200+ 企业服务 + csglite 30 分钟部署)
**行动建议**:
- [ ] 评估三个赛道的"周期位置"——旗舰模型赛道已出现明显头部(智谱 / Mistral / DeepSeek),基础设施赛道仍在大量投入期,工具链赛道(HF / OpenCSG)处于规模化前夜
- [ ] 投资标的需关注"主权属性"——是否能进入本国 / 本地区监管的"白名单"
- [ ] 关注"协议生态"——MCP / A2A / AAIF 的会员资格是工具链赛道的关键资产
- **风险提示**:主权 AI 投资受地缘政治影响显著,需评估"出口管制"与"投资审查"的双向风险

## 四、个人决策者(职业 / 学习 / 工具选择)

### 决策 7:个人 / 小团队开发者,如何选择 AI 模型与工具链?

**对应案例**:10.6 + 10.7
**决策依据**:
- **个人主权**:Ollama 月下载 5200 万 / AI PC 渗透率 54.7% / RTX Spark 本地 120B 模型 38 tokens/秒
- **开源生态**:HF 179 万+ 模型 / OpenCSG 5000+ 模型 / csglite 30 分钟 13B-70B 部署
- **旗舰模型**:Mistral Large 3(欧洲合规)/ GLM-5.2(中文能力 + 国产算力)/ DeepSeek V4-Flash(性价比 1 元/百万 token)
**行动建议**:
- [ ] 评估自身场景的"数据敏感度"——高敏感场景优先本地部署(Ollama + csglite)
- [ ] 评估"语言 / 任务"匹配——中文场景优先 GLM-5.2 / Qwen3.6,欧洲合规场景优先 Mistral,代码 / 推理任务优先 DeepSeek
- [ ] 关注 MCP / A2A 协议生态——9700 万 SDK 月下载 / 150+ 组织支持的工具链集成能力是关键
- **风险提示**:个人 / 小团队的"模型版本管理"与"安全更新"是长期挑战,建议建立内部 SOP

---

## 总结:第十章决策清单的三条元原则

1. **主权 AI 不是"国家内部的事",而是"国家间协议 + 产业间协议"的事**——10.5 案例 3 的 SoftBank × 法国 5 GW 园区是最佳证据。
2. **开源生态主权 = SDK 兼容 + 模型可下载 + 部署门槛足够低**——10.6 的 Hugging Face + OpenCSG 呈现了这一公式的两个版本。
3. **主权 AI 旗舰模型 = 资本背书 + 全栈可控 + 实战验证**——10.7 的 Mistral 与智谱呈现了这一公式的两种范式。

任何 2026 年中的 AI 主权决策,都需在这三条元原则的具体组合下做出选择。
