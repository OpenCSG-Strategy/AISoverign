# 附录F　开源许可证与数据治理速查

这份速查表帮助管理者在项目上线前快速发现问题，不构成法律意见。具体项目要结合许可证原文、所在司法辖区、数据来源、合同条款和产品的分发方式，由专业人员判断。第九章讲许可证背后的制度，第十章讲高质量数据，这里只列上线前至少要确认的事。

## 上线前检查清单

| 对象 | 上线前至少确认 |
|---|---|
| 代码 | 用的是什么许可证；我们有没有修改；产品是否对外分发或以服务形式提供；许可证是否要求公开修改后的源码，或者保留版权声明和 NOTICE 文件 |
| 模型权重 | 权重、代码和分词器（tokenizer）各自是什么许可；是否允许商用、微调、再分发、以托管服务形式提供；有没有用户规模、使用领域或地区上的限制 |
| 数据集 | 谁拥有或授权；是否含个人信息、受版权保护的内容或数据库权利；能否用于训练、评测和再发布；有没有数据卡 |
| 提示词与知识库 | 是否包含客户的商业秘密、个人信息或第三方受限制的内容；谁能读取，谁能修改，修改有没有版本记录 |
| 智能体与工具凭证 | 凭证属于谁；按任务发放的最小权限是什么；多久失效；每次调用有没有日志 |
| 生成内容 | 是否需要标注来源或标注由 AI 生成；是否可能包含受保护的内容或敏感信息；对外发布前由谁审核 |
| 导出与退出 | 所有关键资产能否以通用格式导出；导出后另一套系统能否真的跑起来；上一次导出演练是什么时候 |

## 几个常见的坑

**只看模型的许可证，不看别的部分。** 一个开放模型的权重、推理代码和分词器可能分别用不同的许可证，其中任何一个限制商用，整个产品都受影响。

**把“可以下载”当成“可以商用”。** 能从公开社区下载，只说明对方允许你拿到它。能不能用在收费产品里，要看许可证原文。

**微调以后忘了上游的约束。** 在一个开放模型上微调出来的新模型，通常仍受原模型许可证的约束，再分发时要一并遵守。

**数据集的授权链断在中间。** 一个公开数据集可能汇集了几十个来源，其中有的来源本身就不允许商用。数据卡里要写清每个来源的授权状况。

**智能体的凭证用员工的个人账号。** 员工离职或调岗，凭证没人收回；出了事，日志里分不清是人做的还是智能体做的（第五章、第二十八章）。

**导出只导了原始文件。** 资料导出来了，提示词、评测集、权限设置和运行记录没导出来，换到另一套系统里照样跑不起来（第二十四章）。

## 建议的节奏

立项时填一遍这张表，标出不确定的项，交法务和数据治理负责人确认；上线前再核对一遍，确认没有新增的组件；之后每次更换模型、新增数据源或对外分发方式改变时，重新核对相关的行。
