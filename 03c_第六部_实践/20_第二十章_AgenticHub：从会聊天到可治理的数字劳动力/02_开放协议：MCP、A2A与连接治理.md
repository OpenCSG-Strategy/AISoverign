## 开放协议：MCP、A2A 与连接治理

智能体要成规模，不能每接一个工具就做一次私有集成。十个智能体接二十个工具，按老办法要写两百个接口，换一个模型又得重写一遍。

二〇二四年十一月二十五日，Anthropic 发布了模型上下文协议（Model Context Protocol，MCP），称它是一个“把 AI 助手连接到数据所在系统”的开放标准。[^p20-mcp-launch] 第二章讲过，谷歌在二〇二五年四月发起了让不同公司的智能体互相沟通的 A2A 协议（Agent2Agent），发布时有五十多家机构支持，到二〇二六年四月超过一百五十家；二〇二五年十二月，MCP 也交给了 Linux 基金会旗下的智能体 AI 基金会管理。[^p2-agent-protocols] MCP 管模型和工具、数据源之间怎样连接，A2A 管智能体和智能体之间怎样分工、交接。

开放协议对主权的意义，在于接口公开、含义稳定，新的供应商可以进来，组织不必把全部工具和智能体锁在一个平台里。第七章打过一个比方：换掉了发动机，方向盘、刹车和钥匙却只认原厂。工具都按公开协议接入，换一个模型或者换一个智能体平台，工具那一侧可以不动。这对应六种能力里的替换和组合。

CSGHub 把 MCP 服务当成一类资产来管，可以像模型一样建仓库、写说明、做版本，多源同步也能把公共社区里的 MCP 服务拉进私有部署；它的平台架构里，模型网关旁边有一个专门的 MCP 网关。[^p18-csghub-docs] 截至二〇二六年十月，OpenCSG 的公开文档里没有查到对 A2A 协议的支持说明。

协议开放了，不等于安全。默认权限给多大，身份怎样一层层传下去，凭证存在哪里，工具对自己的描述和返回的结果能不能信，每一处都可能被人利用。MCP 的规范自己就提醒，工具对自己的描述不能直接当成可信的事实；它的授权规范还明确规定，不能把客户端拿到的令牌原样转交给下游服务。[^p9-mcp-control] 第五章讲房卡时引用过这一条。一个被污染的工具描述，可以借智能体之手，穿过原本彼此隔开的系统。

把 MCP 服务收进统一的仓库和网关，要紧的是登记。每一个工具从哪里来，哪个版本，谁批准接入，哪些智能体能调用，调用时用的是谁的身份，都登记在一个地方，出了事才有处可查，要断开时也知道断哪一根线。网关能做的是把连接集中起来，让它能被看见、能被关掉。每个工具该给多大的权限，仍然要由人来判断。

> **行动页｜给智能体和它们的连接建一本花名册**
>
> - 登记组织里每一个在运行的智能体：责任人，代表谁办事，用哪个模型，能调用哪些工具，什么时候复审。
> - 把智能体接入的工具和 MCP 服务逐个登记来源和版本，没人认领的先断开。
> - 检查有没有把员工账号或管理密钥直接交给智能体的情况，改成按任务发放、到期作废的凭证。
> - 挑一个智能体做一次下线演练：撤销身份，关掉接口，确认下游业务没有断。
