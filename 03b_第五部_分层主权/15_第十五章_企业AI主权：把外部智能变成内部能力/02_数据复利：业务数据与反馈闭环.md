## 数据复利：业务数据与反馈闭环

在所有智能资产里，数据最特别。模型、框架和工具会过时，爱彼迎的客服智能体一用就是十三个模型，哪个快、哪个便宜就多用哪个。高质量的业务数据和反馈却会越攒越多，越用越值钱，像复利一样。

模型每一次的输出用完就过去了，企业最该积累的，是那些只有自己能产生的东西：客户真实提出的问题，专家改过的稿子，销售赢单和丢单的原因，设备的故障记录，合同里的风险条款，代码里的缺陷，客服收到的投诉。这些材料整理成结构化的记录，标清谁能用、用来做什么、是哪个版本，再进入评测和学习，组织的能力就会一轮一轮往上走。第五章讲过怎样分拣这类反馈：一部分变成测试题，一部分写成业务规则，一部分更新知识库，只有审查过的少量材料才拿去训练。

反过来的情况更常见。这些经验只留在某个软件服务的隐藏记忆里，留在某位员工的聊天记录里，或者留在一个导不出来的向量数据库（把文字转成一串数字、供模型检索用的数据库）里。企业用 AI 越多，积累就越多地落在平台一侧，依赖也就越深。

### 数据也会往外流

数据还可能在没人注意的时候留在别处。二〇二五年五月十三日，在《纽约时报》起诉 OpenAI 和微软侵犯版权的案子里，美国纽约南区联邦法院的治安法官奥娜·王（Ona T. Wang）命令 OpenAI 保存并单独存放 ChatGPT 的全部输出日志，用户已经删除的对话也在其中。在这之前，用户删掉的对话一般在三十天内从系统里清除。命令落在普通的 ChatGPT 用户和 API 用户身上，ChatGPT 企业版、教育版，以及签了零数据保留协议的 API 客户不受影响。这项保存义务到二〇二五年九月二十六日才结束。[^p15-openai-preservation]

一家公司的员工如果用个人账号把合同和代码贴进对话框，这四个多月里，这些内容就和一场与公司无关的官司绑在了一起，删也删不掉。同一家供应商的客户里，签了企业合同或零数据保留协议的公司，就在这道命令之外。

所以要给数据划路。哪些数据可以送到外部模型，哪些只能在本地模型上处理，哪些根本不该交给模型，在模型网关这一层就决定好。供应商的合同里写清楚，企业的数据和反馈能不能被拿去训练对方的模型，合同结束以后多久删除。

第十章已经从更大的视角讲过，高质量数据为什么值得长期积累。放到一家企业里，有一个简单的检验办法：换掉当前的模型供应商以后，下一个模型能不能用上过去三年积累的测试题、改稿记录和失败案例。
