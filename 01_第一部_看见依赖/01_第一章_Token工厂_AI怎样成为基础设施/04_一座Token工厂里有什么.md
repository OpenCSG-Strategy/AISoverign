## 一座Token工厂里有什么

“工厂”不是指一栋摆满GPU的建筑。它是一条从能源到业务结果的完整生产链。

| 工业体系 | AI体系 | 它实际完成什么 |
|---|---|---|
| 建厂 | 预训练 | 用数据、算力与优化算法形成模型权重 |
| 生产设备 | 训练后的模型 | 在推理阶段反复运行的认知机器 |
| 改造生产线 | 后训练、微调、蒸馏、量化 | 改变行为、任务适配、规模或运行成本 |
| 即时供料 | 提示、上下文、RAG、数据库 | 在运行时补充任务需要的事实与材料 |
| 厂房设备 | 加速器、显存、网络、存储、数据中心 | 决定容量、速度、可靠性与可部署范围 |
| 能源 | 电力与冷却 | 驱动计算并带走热量 |
| 排产 | 调度、批处理、缓存、模型路由 | 在延迟、吞吐和成本之间分配资源 |
| 中间产物 | 输入与输出Token | 可计量，但不直接等于质量或价值 |
| 良品检验 | 评测、事实核验、安全测试、人工复核 | 判断输出能否进入真实工作 |
| 生产控制 | AgenticOps | 管理模型、工具、权限、版本、轨迹与事故 |

其中最容易被忽略的是“即时供料”。基础模型读过很多材料，却不知道你公司的今日库存、病人刚刚更新的检查、昨天通过的新规定。RAG——检索增强生成——先从外部知识库寻找相关材料，再把材料放进当前上下文；数据库和工具调用则提供最新状态。它们不会把事实永久写进模型权重，而是在一次任务中把所需信息送到生产线旁。

这个区别很重要。训练数据决定机器形成了怎样的基础能力；当前上下文决定它此刻看见了怎样的世界。模型很强，不等于上下文正确。检索到过期资料，强模型也可能沿着错误前提给出漂亮答案。

同样，生产指标也必须分层。

首个Token出现时间决定用户等多久；连续Token之间的间隔决定回答是否流畅；系统总吞吐量决定同一时刻能服务多少请求；高峰期的尾部延迟决定最慢的用户会等多久。MLPerf等推理基准把性能测试和准确度目标放在一起，正因为单独追求速度会失去比较意义。[^p1-mlperf]

最终还要问一个比“每秒多少Token”更困难的问题：系统完成了一项正确任务，究竟花了多少钱？如果模型生成了一万Token，最后仍需专家从头重做，这些Token不是产值，而是返工成本。
