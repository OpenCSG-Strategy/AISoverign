# 第十二章　开源生态：主权为什么需要社区

二〇二五年五月七日，PyTorch 基金会在巴黎宣布扩展成一个“伞形基金会”，除了深度学习框架 PyTorch 本身，今后还托管覆盖训练、推理、部署和智能体等环节的其他项目。第一批进来的有两个：源自加州大学伯克利分校的大模型推理引擎 vLLM，和微软开发的分布式训练库 DeepSpeed。[^p12-pytorch-umbrella] 十月二十二日，最初由 Anyscale 公司开发的分布式计算框架 Ray 也加入进来。按基金会的说法，训练用 PyTorch，推理用 vLLM，分布式执行用 Ray，三个项目从此有了一个中立的共同归属。[^p12-ray]

这个基金会本身就是一次交权的结果。二〇二二年，Meta 把自己开发的 PyTorch 交给 Linux 基金会，成立了 PyTorch 基金会，AMD、亚马逊云科技、谷歌云、微软 Azure 和英伟达都进了创始理事会。[^p12-pytorch-foundation] Meta 少了一些控制，竞争对手们却更愿意往里投入：芯片公司愿意为它做适配，云厂商愿意把它当默认选项，开发者也不必担心哪天它变成某家公司的专属工具。到二〇二五年，基金会已有三十多家成员公司，[^p12-pytorch-umbrella] 别的项目愿意搬进来，看中的也是这一点。

同一年年底，同样的事情发生在智能体领域。十二月九日，Linux 基金会宣布成立智能体 AI 基金会（Agentic AI Foundation），Anthropic 交出了模型上下文协议 MCP，金融科技公司 Block 交出了智能体框架 goose，OpenAI 交出了给编程智能体写说明的 AGENTS.md 规范。亚马逊云科技、谷歌、微软、彭博社、Cloudflare 等公司是白金会员，Hugging Face 也在会员名单里。[^p12-aaif] 第二章讲过 MCP 的来历，它从一家公司发起的接口，变成了竞争对手们共同管理的公共标准。

这几家公司彼此竞争得很激烈，却愿意把关键的底层部件放进同一个公共机构。底层部件只有大家都用、都信得过，才能成为标准；成了标准，每家公司在上面做自己的生意都更省力。
