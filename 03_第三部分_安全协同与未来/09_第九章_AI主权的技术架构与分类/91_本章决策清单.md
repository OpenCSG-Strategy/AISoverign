# 第九章 决策清单

> 读完本章后,无论你是企业决策者、政府政策制定者还是个人开发者,都可以用以下清单自检或推进行动。

## A. 给企业决策者(CTO / CIO / CDO)

### A1. 五层主权自检(给自己打分)
- **数据层**:是否有自建 / 授权语料库?数据空间接入情况?是否部署联邦学习 / TEE?
- **模型层**:开源权重与闭源 API 的组合比例?许可证合规(月活上限、再分发权)?
- **算力层**:是否依赖单一芯片供应商?是否规划多云 / 国产芯片备选?
- **协议层**:是否部署 MCP / A2A 客户端?是否参与 AAIF / 国产协议治理?
- **应用层**:终端用户体验是否锁定单一厂商?数据沉淀是否可迁移?

### A2. 路线组合(2026 工程实践建议)
- **"1+1+1 三件套"**:一个本地开源权重(可控)+ 一个商业 API 备选(应对突发能力需求)+ 一个联邦隐私层(处理敏感数据)。
- **避免单一押注**:纯 API 在 2026 年面临合法性压力;纯自托管开源在性能 / 运维上负担过重;混合是现实平衡。

### A3. 模型托管平台选型
- 评估**合规路径**而非"开源 vs 闭源"——HF(美国主体,受 CLOUD Act 约束)与 OpenCSG CSGHub(国内主体,默认数据不出境)在合规债上差异巨大。
- 对受合规约束的国内组织,本土平台不只是"支持国产",更是"主权债"层面的现实考量。

### A4. 协议层参与
- 不要只把 MCP / A2A 当技术接入,要**参与治理**——加入 AAIF 或本土协议组织,让自己的诉求能被写进标准。
- 协议治理权集中在白金会员手中,不参与就只能接受别人的标准。

## B. 给政府政策制定者

### B1. 五层国家级技术栈诊断
- 逐层评估本国技术栈的"主战场 + 副战场 + 空白":
  - 数据层是否有国家级语料库 / 数据空间?
  - 模型层是否有可识别的主权旗舰?
  - 算力层是否有可获得性 + 可控性?
  - 协议层是否参与治理?
  - 应用层是否有本土生态?
- **主权完整度看最弱一层**,不看最强一层。

### B2. 路线选择
- 没有"最优路线",只有"国情匹配路线"——美国 B+A、中国 A+E、欧盟 C+D+E、中东 E、印度 A+C+D。
- 避免被"全栈国产"或"全栈开放"的口号绑架;**关键是有可识别的"主权路径"**。

### B3. 协议治理
- AAIF 白金会员几乎全是美企,这是 2026 年最显著的非对称优势。
- 推进本土协议组织(MCP / A2A 本土分支、AAIF 区域工作组)或在 AAIF 争取话语权,是国家主权博弈的下一站。

### B4. 国家算力公共池
- 印度 IndiaAI 38K GPU 公共池 + 韩国 MSIT 35,200 B200 已储备 + 50,000 政府专用 2028 计划 + 法国 Campus AI 1.4 GW 园区——这些都是"国家级 AI 算力公共池"的样板。
- 避免让"主权 AI"沦为少数巨头的私有资产,公共池是"主权能力下沉的必要条件"。

## C. 给个人开发者

### C1. 模型选型
- 不要被基准排名绑架;**主权属性与性能同等重要**——Apache 2.0 / MIT 优于 Llama 4 社区许可(700M MAU 上限)。
- 个人 / 中小团队优先考虑 Apache 2.0 / MIT 许可模型,避免未来业务扩张时的许可证纠纷。

### C2. 协议使用
- 学习 MCP / A2A——这是 AI 时代的基础设施技能,类比 2010 年代的 REST API。
- 在 IDE / SaaS 中优先选择支持 MCP 的产品(Cursor、Claude Code、Zed 等),让自己的工具栈具备"AI 可调用"的能力。

### C3. 模型托管平台
- 在 HF 关注全球生态,在 OpenCSG CSGHub 关注国内生态——双线关注能更全面理解 AI 主权版图。
- 如果做企业级项目,提前评估"主权债"——HF 主体在美国,受 CLOUD Act 约束;CSGHub 在数据合规上对国内项目更友好。

## D. 通用检查问题(任何组织 / 个人可用)

1. 我所在组织 / 国家的 AI 主权大厦,**最弱的一层是哪层**?如何补?
2. 我选择的模型 / 平台 / 协议,**许可证与合规属性是什么**?迁移成本多大?
3. 我参与或依赖的协议层,是否参与治理?如果不参与,我的诉求能写进标准吗?
4. 我的数据层是否真正"数据不出域"?如果依赖外部,主备方案是什么?
5. 我的算力层是否依赖单一供应商?是否有"主备 + 多云"组合?
6. 我采购的"主权云",是"主权云"还是"营销话术"?具体看**数据存储位置、合规审计能力、退出机制**三项。
