## 高质量数据工厂：从原始数据到可审计资产

企业手里的数据很多，能直接拿来训练、检索和评测的很少。重复的记录，过时的制度，格式不一的扫描件，混着客户隐私的聊天记录，来源不明的外购数据，都要经过加工才能用。

这套蓝图的目标，是把原始数据加工成可训练、可检索、可评测、可审计的数据资产。流程大致是：盘点有哪些数据；确认每一份的许可和合规条件；去重、清洗；处理敏感信息；标注；抽检质量；写数据集说明书；做版本管理；用于训练或评测；再把使用结果反馈回来。在 OpenCSG 的产品里，数据集作为资产放在 CSGHub 里管版本和权限，DataFlow 负责接入、清洗、转换和协作标注。[^p18-dataflow] 去重、敏感信息识别这几步，公开文档没有写到，需要另配工具。

数据工厂最容易被考核成处理了多少 TB。这个数字只说明机器转了多久。我们建议看下面这组指标：

| 指标 | 回答的问题 |
|---|---|
| 可用样本比例 | 加工以后，多少数据真的能用 |
| 重复率、错误率 | 数据干不干净 |
| 覆盖率 | 业务里的主要情况和少见情况有没有都覆盖到 |
| 标注一致性 | 不同标注员对同一条数据的判断是否一致 |
| 许可完整率 | 多少数据的使用权利有据可查 |
| 评测提升 | 用了这批数据，模型在评测集上进步了多少 |
| 真实任务改善 | 业务上的返工、投诉、处理时间有没有变化 |
| 可用周期 | 一条数据从产生到能用，要多少天 |

许可完整率这一项最容易被忽略，出了问题代价最大。一批来源说不清的数据混进训练集，模型上线以后才发现，要么重新训练，要么带着法律风险继续用。第三章讲迁移时提到，欧盟的《数据法》和《通用数据保护条例》已经把“能不能带走”“能不能用”变成了法律问题。[^p1-gdpr][^p1-data-act]

这套蓝图管不到的，是数据背后的人和利益。一家工厂愿不愿意把产线上的真实缺陷数据拿出来，取决于它信不信这些数据不会流到竞争对手手里。数据工厂能提供权限、审核和记录，信任要靠合同、制度和时间建立。
