# 附录C　AgenticOps 方法手册

正文讲了为什么要管住会行动的AI：第三章讲控制权和六种能力，第十二章讲授权、刹车、模型网关和三本账，第十四章讲四层参考架构，第十七章讲任务和协议，第二十一章讲从一项真实任务起步的路线图。这份附录只收动手搭系统时要查的结构化内容，不做技术工作的读者可以跳过。

## 从 DevOps 到 AgenticOps

| 方法 | 主要管什么 | 单独使用时的缺口 |
|---|---|---|
| DevOps（开发运维一体化） | 代码、服务、基础设施 | 判断不了概率输出和任务结果对不对 |
| MLOps（机器学习运维） | 数据、实验、模型版本和漂移 | 通常不覆盖工具链、委托身份和外部后果 |
| AgenticOps | 任务、智能体、模型、上下文、工具、权限和结果 | 仍需要法律、组织责任和行业判断来约束 |

2025年，开源模型社区OpenCSG在一篇公开文章里提出AgenticOps的说法，把智能体的生命周期分成提示、编码、构建、测试、发布、部署、运行和再训练八个环节。[^p4-agenticops-origin]业界也常用AgentOps，含义从可观测性到完整的生命周期管理都有，名称至今没有统一。[^p4-agentops-landscape]本书用AgenticOps指一整套方法：任务有边界，身份认得出，行动管得住，过程看得见，结果验得了，失败收拾得了。

## 三个循环和一个控制面

**交付循环**：准入、设计、构建、评测、发布。决定什么任务值得交给智能体，模型、提示、知识、工具和权限怎样组成一个认得出的版本，拿到什么证据才能上线。

**运行循环**：发生在每一项真实任务里。谁发起，智能体代表谁，这一步需要什么权限，外部动作有没有真的成功，什么时候必须停下来问人。

**学习循环**：收集反馈、分析事故、做出变更、重新评测，必要时让智能体退役。真实的失败变成回归测试，人工修改暴露规则空白，投诉揭示评测没覆盖到的人群。

三个循环共用一个控制面，保存几组对应关系：任务和责任人，智能体和身份，工具和权限，组件和版本，测试和发布门，运行轨迹和外部结果，成本和预算，事故和退出路径。控制面不必是一个平台，身份系统、工作流、模型网关、资产仓库、评测服务、运行遥测和审批制度组合起来就可以，要紧的是一项任务的信息能从立项一路连到结果和补救。控制面在四层参考架构里的位置见第十四章。

### 六类工程方法

2025年到2026年间，智能体工程里逐渐形成了六类互相衔接的做法。[^p4-agent-engineering-methods-2026]

| 方法 | 改造什么 | 典型动作 | 容易被误解成 |
|---|---|---|---|
| 提示工程 | 单次推理的指令 | 写清角色、约束、示例和输出格式 | 管理了全部上下文 |
| 上下文工程 | 每一步模型实际看到的信息 | 按需检索、压缩历史、维护工作记忆 | 把资料全塞进窗口 |
| 工具与技能工程 | 智能体能调用的行动接口 | 缩小工具范围、校验参数、写清返回含义 | 接上应用程序接口（API）就算集成完了 |
| 运行装置工程 | 模型外侧推动任务的整套环境 | 设计循环、计划、状态、检查点、恢复、批准和沙箱 | 买一个开发框架 |
| 评测驱动开发 | 能力和变化的验收方式 | 先定任务和评分规则，多次试验，检查轨迹和外部结果 | 只看最终回答或排行榜 |
| 轨迹驱动优化 | 已发生任务留下的过程证据 | 从失败轨迹里挑案例重放，比较改动 | 把所有日志拿去训练 |

运行装置（Harness）决定每一轮给模型看什么、允许碰哪些工具、状态写在哪里、失败后从哪里恢复。2025年11月到2026年2月，Anthropic和OpenAI先后公开了各自的运行装置工程做法，结论相近：工程对象已经从“调好一个模型”扩大到“设计模型所在的工作环境”。[^p4-harness-engineering-2026]深度求索开源DeepSeek Harness一事见第二章和第十四章。[^p4-deepseek-harness-2026]运行装置本身也要有版本、要评测、要退役，旧的运行装置为旧模型补上的限制，换了新模型以后可能变成累赘。

## 八类要一起登记的对象

| 对象 | 要回答的问题 |
|---|---|
| 目标 | 谁定义的任务，成功和禁止的条件是什么，目标变了旧任务要不要继续 |
| 主体 | 人、组织、智能体、外部服务各是谁，谁代表谁，责任能否沿委托链还原 |
| 上下文 | 数据从哪来，新不新、全不全、可不可信，敏感信息有没有超出必要范围 |
| 系统版本 | 实际跑的模型、提示、知识、记忆策略、工具说明和运行环境是什么 |
| 工具 | 谁提供，版本可不可信，参数和返回怎样校验，动作能不能撤回 |
| 权限与凭证 | 能访问什么、做什么、多久、能否再委托、怎样收回 |
| 任务状态 | 执行中、等输入、等批准、失败、取消还是完成，重试安不安全，预算还剩多少 |
| 外部结果 | 现实里哪些状态已经改变，是否真的完成，能否撤销、补偿、向受影响的人说明 |

任何一项脱节都会制造责任断点：日志记下了工具调用，却不知道用的谁的权限；任务标着“完成”，却没有外部订单号。所以组织最先需要一本智能体登记册，写清有哪些智能体，服务什么任务，谁负责，用了哪些高风险工具，碰哪些敏感数据，当前版本和评测状态，怎样暂停和退役。影子智能体的风险见第二十二章。

## 运行循环的五项要求

一份可用的执行凭证要连起：谁发起、目的是什么，用了哪些智能体、模型、提示、知识和工具版本，输入从哪来，拿到什么权限，哪里发生过重试、降级或人工批准，改变了哪些外部状态，结果有没有被外部系统确认。它记录能核对的事实，模型的“内心独白”不必当证据保存。OpenTelemetry（开源的可观测性标准项目）的生成式AI语义约定正在统一这类字段，并默认不采集提示内容和工具参数。[^p1-otel-genai]

- 看得见：任务、身份、来源、版本、工具和外部状态能关联起来。
- 管得住：数据、资金、时间、工具和委托层数按风险设限，高风险动作过独立的规则或人工检查。
- 停得下：能取消任务、收回凭证、暂停单个工具，把系统降到只读或交给人工。
- 退得回：关键状态有快照，重复调用尽量不产生重复后果，版本能回退，已经造成的后果有补偿办法。
- 说得清：出现争议时，能根据当时的任务、依据和批准说明发生了什么。

告警必须有负责人、响应时限和能执行的措施。

## 学习循环的分流

反馈进入学习之前，先问五件事：有没有权利用来改进，代表哪些人群和任务，质量怎样核验，人工修改是偏好、纠错还是制度要求，保留多久、谁能删除。

| 失败的原因 | 先改哪里 |
|---|---|
| 模型没理解任务 | 提示、示例，或换模型 |
| 检索到了旧制度 | 知识库和时效机制 |
| 工具参数错了 | 参数校验 |
| 权限给宽了 | 授权 |
| 任务目标含糊 | 任务说明 |
| 人总是否决某类动作 | 考虑这件事不再自动做 |

再训练只是其中一条路，往往最贵、最难解释。任何变更都要重新过发布门，旧版本的测试结果不能自动继承。退役也是正式阶段：撤销身份和接口，处理剩余数据，保存必要证据，解除下游依赖。[^p4-agent-lifecycle-2026]

## 控制面的七类关系

联邦式控制面提供公共的身份和信任根、能力目录、协议和数据契约登记、策略模板、模型和工具登记、任务路由、跨部门的状态和审计索引。它不默认保存各部门完整的提示、检索片段和原始日志，规则冲突时按“共同底线加本地收紧”处理。跨部门任务用一个共同任务编号串起各部门签发的最小记录，详细证据留在本地，获得授权的调查者沿编号调取。[^p9-otel-control]

控制面要长期维护七类关系：

1. 任务和能力：哪项任务用哪种模型、工具或人。
2. 数据和计算：原始材料留在哪，经过批准的哪些字段能出去。
3. 身份和行动：谁代表谁，为哪项任务，多长时间，对什么对象能做什么，用短期、可撤销的凭证表达。
4. 版本和评测：每次变化都经过评测和小范围试运行。
5. 运行和证据：完整调用链看得见，可以导出。
6. 反馈和资产：人工纠正、失败样本、申诉变成企业自己的评测题、规则和知识。[^p6-data-work]
7. 事故和退出：能暂停、降级、回滚，保留证据，必要时整体迁走。

分布式云和可信执行环境能把边界延伸到物理位置之外，但它们证明的是软硬件状态符合某项信任策略，证明不了代码逻辑正确、模型输出可靠。[^p6-confidential-hybrid]控制面自己也要能替换，能力目录、任务状态、策略和执行凭证锁在私有格式里，等于把锁定往上挪了一层。

## 模型网关与机器预算

模型网关的作用和备用模型的要求见第十二章。查表时记住三条：路由规则要拿企业自己的评测数据校准，按难度分配大小模型的研究表明成败取决于对回答质量的估计准不准；[^p6-model-routing]网关只管得到经过它的调用，应用自身的权限和业务校验仍要保留；路由规则、日志格式和接口要能导出。

平台用积分（Credits）计价时，可信的任务结算至少满足四个条件：

- 兑换透明：一单位积分能买什么，费用怎样构成，规则变化能追溯。
- 结果可验：谁来定义完成，用什么证据，失败和部分交付怎样处理。
- 预算可执行：智能体只能在明确的额度、用途和时间内采购，超限就停。
- 账本可迁移：任务记录、费用明细和履约证据能导出。

2025年谷歌发布的智能体支付协议（Agent Payments Protocol，AP2）用签名的授权和收据把人的意图、智能体生成的订单和最后的付款连起来，国际货币基金组织的一份工作人员说明（只代表作者观点）把它放在“控制与授权”这一层。[^p6-agent-payments]身份、评测和争议解决成熟以前，智能体之间自动交易仍是有待检验的设想。

## 最低可行版本

一个小团队可以从一张任务单、几个独立账号、一套真实测试和一次停止演练开始：

1. 给每个重要的智能体指定一个责任人。
2. 列出它会接触的数据、工具和外部影响。
3. 把高风险动作放到独立的确认点。
4. 运行中只保存足够复盘的版本和结果证据。
5. 用真实的失败攒一个小评测集。
6. 让备用路径平时承担少量任务。
7. 定期收回过期权限。
8. 实际演练一次停止、接管和导出。

规模大了，再逐步加上统一登记、自动发布门、动态授权、全链路遥测、事故响应和资产治理。管控强度随数据敏感度、行动权、影响人数、不可逆程度和运行时长一起提高。检验一套AgenticOps是否落地，可以看上一次停止演练是什么时候，谁在几秒内按下了停止。
