## 价值链：从 GPU 小时到验证过的结果

算力生意的计费方式，几年里换了三次。最早按 GPU 卡、按小时或者按云主机实例收费，客户租的是机器。模型接口出现以后，改成按 Token 收费，客户买的是模型生成的文字。智能体开始替人做事以后，客户最终想买的是完成任务的结果：一份审完的合同，一张处理好的工单，一笔对过账的报销。

把这条链从头到尾写出来，大致是：能源，算力，模型，Token，智能体，任务，验证过的结果。越往右，离业务价值越近；越往左，越容易计量，也越容易被当成目标本身。一座城市报自己有多少 P 的算力，一家企业报这个月用了多少亿个 Token，都停在链条的左半段。第六章说过，算力最容易被写成一个大数字，却说明不了谁能用上、花了多少钱、用完以后留下了什么。

所以 Token 工厂不能理解为给算力中心换一个名字。它是一套把能源、算力、模型、数据、路由、智能体和评测连起来的生产体系。第一章那个合同审查的例子里有五道工序：备料，开机，厂房配合，排产，验货。少了最后一道验货，前面生成得再快，也只是把错误更快地送到用户面前。

城市和企业真正要优化的，是单位有效结果的综合成本、质量、时延和可持续性。第五章的三本账可以拿来用：资源账记 Token、算力、工具调用和人工各花了多少；任务账记成功率、耗时、重试次数和总成本；结果账记客户的问题解决了没有，有没有引来投诉和返工。一座 Token 工厂如果只报资源账，它和过去的算力中心没有本质区别。

软件在这条链上能做的，是把中间几段连起来，并且让每一段都有数可查。按 OpenCSG 的产品文档，CSGHub 的模型网关是应用调用 AI 服务的统一入口，既能接企业自己部署的推理服务，也能接外部模型供应商；同一个模型可以配置多个上游，按路由规则分流，做健康检查，一个出故障就切到另一个；用户可以看到请求量、费用、首个 Token 的等待时间和缓存命中率。[^p21-ai-gateway] 二〇二六年九月的版本又加入了按用户意图选择模型服务的语义路由。[^p18-csghub-docs] 平台的算力管理部分支持按 GPU 时长和按 Token 两种口径计量。[^p17-csghub-architecture]

这些功能管的是资源账和一部分任务账。结果账要靠业务部门自己定义什么算“做成了”，再把验收结果接回来。没有这一步，计量做得再细，也只是把左半段算得更清楚。
