## 分叉退路：从 OpenTofu 到 Valkey

HashiCorp 的事并非孤例。二〇二四年三月二十日，内存数据库 Redis 的同名公司宣布，从 7.4 版起，Redis 不再以 BSD 许可证（一种很宽松的开源许可证）发布，改为在 Redis 源代码可用许可证第二版（RSALv2）和服务器端公共许可证（SSPL）之间二选一。公司在公告里承认这两种许可证都不在 OSI 认可的名单上，Redis 从此不再算开源软件。它的理由是，大型云服务商拿 Redis 做托管服务赚钱，出钱出人开发的却主要是 Redis 公司自己。新许可证不影响企业内部使用，但不再允许别人把它当作托管服务卖给第三方。[^p8-redis-license]

八天以后，三月二十八日，Linux 基金会宣布成立 Valkey 项目，从仍以 BSD 授权的 Redis 7.2.4 继续开发，亚马逊云科技（AWS）、谷歌云、甲骨文、爱立信和 Snap 等公司表态支持。[^p8-valkey]

更早一些，搜索引擎软件 Elasticsearch 也走过这条路。二〇二一年一月，开发它的 Elastic 公司把许可证从 Apache 2.0 改成 SSPL 和自家的 Elastic 许可证，亚马逊在同年四月推出了分叉项目 OpenSearch。二〇二四年八月二十九日，Elastic 又给 Elasticsearch 和 Kibana 的源代码加上了 OSI 认可的 AGPL 许可证选项。[^p8-elastic-agpl] 二〇二五年五月一日发布的 Redis 8 也加上了 AGPLv3。[^p8-redis-license]

我们并不认为改许可证的公司都做错了。一家公司养着一个被全世界免费使用的项目，大部分收入却流到了云厂商那里，它想改规则可以理解。更要紧的是用户这一边。几次改许可证，用户都没有被新条款困住，原因是旧版本的开源授权收不回来，代码在社区工程师手里，又有中立的基金会可以接手。少了其中任何一样，分叉都很难成。

分叉也有代价。两个版本会越走越远，插件和文档要维护两套，社区的精力被拆散。很多企业其实从没真的切换过去。它们得到的好处来自切换的可能：原厂知道客户随时能走，定价和条款就不容易离谱。

对 AI 主权来说，这是开源最实在的用处。一个组织在评估自己的依赖时，可以拿每个关键组件问一句：如果它的主人明天改了规则，我们和同行有没有能力、有没有法律上的许可，从今天的版本接着做下去？能做到，这份依赖就还在可以谈判的范围里。
